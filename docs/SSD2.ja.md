# SSD を 2 枚使う（STRATA_GLM_MIRROR）

[English](SSD2.md)

GPU とメモリに入りきらないエキスパートは、答えている間も SSD から読みます。DeepSeek V4.1 では、1 トークンの時間の
3〜4 割がこの SSD 待ちです。モデルのファイルを 2 枚目の SSD にもコピーしておくと、Abyss は 2 枚から読み分けて、
この待ちを減らします。

メモリはスロットが埋まっていて足せない PC でも、M.2 の空きがあれば NVMe は足せます。そういう PC 向けの機能です。
買い替えで余った NVMe があれば、M.2 に挿すか USB4 / Thunderbolt のケースに入れて、ファイルをコピーするだけで使えます。
2 枚目は 1 枚目より遅くても構いません（速さに応じて受け持つ量が決まります）。ただし SATA の SSD（約 0.5 GB/s）では、
ほとんど受け持てません。

## どれくらい効くか

DeepSeek V4.1 Flash 1017、unsloth UD-IQ2_XXS（2026-10-28 の版）、AI PRO R9700（OCuLink Gen4 x4）+ iGPU レーン、
tail skip なし。2 系列 x 3 回、1 枚と 2 枚を交互に流した中央値です（2026-10-29）。

- 1 枚目（モデルの置き場所）：Lexar NM790 4TB、内蔵 M.2、6.2 GB/s
- 2 枚目：USB4 の外付けケースに入れた NVMe、3.5 GB/s

| GPU + メモリ | 1 トークン（1 枚 → 2 枚） | 速さ | SSD 待ち（1 トークン） | 2 枚目から読んだ割合 | 起動時の読み込み |
| --- | --- | --- | --- | --- | --- |
| 32 GB + 96 GB | 51.4 → 49.2 ms | +4.5% | 19.7 → 15.7 ms（−20%） | 37〜45% | 5.2 → 6.9 GB/s |
| 32 GB + 64 GB | 71.9 → 59.3 ms | **+21%** | 27.9 → 22.2 ms（−20%） | 38〜45% | 4.4 → 6.5 GB/s |
| 16 GB + 64 GB | 92.0 → 77.7 ms | **+18%** | 42.8 → 34.0 ms（−21%） | 39〜47% | 5.8 → 7.6 GB/s |

- 品質は変わりません（同じファイルを読むだけです）。
- SSD 待ちが大きい構成ほど、速さに効きます。メモリが少ない PC ほど効き目が大きくなります。
- 2 枚目が USB4 で 1 枚目の約半分の速さなので、2 枚目が受け持つのは約 4 割です。同じくらいの速さの M.2 を 2 枚
  使えば、半分ずつ読めるので、SSD 待ちはさらに減るはずです（まだ測っていません。結果の報告を歓迎します）。
- SSD が遅くなる時間帯（ときどき起きます）に当たったときの落ち込みも、小さくなりました。

## 使い方

1. 2 枚目の SSD に、モデルのフォルダと**同じ名前**のファイルをコピーします。全部でなくても構いません。コピーした
   シャードだけ 2 枚から読みます。

   ```bash
   # 例：DeepSeek V4.1 UD-IQ2_XXS を /mnt/ssd2 にコピーする（Engram だけのシャード 6 は不要）
   mkdir -p /mnt/ssd2/V4.1-UD-IQ2_XXS
   cp ~/llm/apps/Abyss-data/models/unsloth/DeepSeek-V4.1-Flash-1017-GGUF/UD-IQ2_XXS/*-0000[1-5]-of-00006.gguf \
      /mnt/ssd2/V4.1-UD-IQ2_XXS/
   ```

2. 設定ファイル（`abyss-<名前>.json`）の `"env"` に、コピー先のフォルダを書きます
   （設定ファイルの場所：[SETTINGS](SETTINGS.ja.md)）。

   ```json
   "env": {"STRATA_GLM_MIRROR": "/mnt/ssd2/V4.1-UD-IQ2_XXS"}
   ```

   設定ファイルを変えずに試すときは、`STRATA_GLM_MIRROR=/mnt/ssd2/V4.1-UD-IQ2_XXS ./abyss.sh --bench --config abyss-<名前>.json` です。

3. サーバーを起動し直します。エンジンのログに、使われたシャードが出ます。

   ```
   [mirror] DeepSeek-V4.1-Flash-1017-UD-IQ2_XXS-00002-of-00006.gguf also read from /mnt/ssd2/V4.1-UD-IQ2_XXS/...
   ```

   エンジンを止めたとき、2 枚からどれだけ読んだかがログに出ます。

   ```
   glm fast mirror CUDA0: 115.01 GB from the shards' drive, 68.46 GB from the mirror (37.3%)
   ```

効いているかは、`./abyss.sh --bench` を `STRATA_GLM_MIRROR` あり・なしで流して比べるのが確実です
（[BENCH](BENCH.ja.md)）。

## 2 枚目に必要な容量

エキスパートの入ったシャードだけで十分です。DeepSeek V4.1 の Engram の表（それだけのシャードが 1 つ、111〜135 GB）は、1 トークン
48 行しか読まないので、コピーしなくても速さはほとんど変わりません。

| モデル | 2 枚目に必要な容量（目安） |
| --- | --- |
| DeepSeek V4.1 unsloth UD-IQ2_XXS | 約 165 GB（シャード 1〜5） |
| DeepSeek V4.1 unsloth UD-IQ1_M | 約 140 GB（シャード 1〜4） |

どちらも **256 GB の SSD で足ります**。交換で外した小さい NVMe も使えます。それより小さい SSD でも、一部のシャードだけ
コピーすれば動きます（例：128 GB に UD-IQ2_XXS の 50 GB のシャードを 2 本）。コピーしたシャードの読み出しだけが 2 枚に
分かれるので、効き目はそのぶん小さくなります（未測定）。

## 仕組み

- 起動時に、1 枚目の各シャードについて、2 枚目に同じ名前のファイルがあるかを見ます。大きさと、先頭と末尾の 1 MiB
  が同じときだけ、2 枚目も使います（違うファイルを読まないための確認です）。
- 読み出しのたびに、2 枚の「今の混み具合」と「最近の速さ」から、早く終わりそうな方を選びます。速さは、読み出しごと
  に測り直します。2 枚の速さが違っても（今回の USB4 のように）、速い方が多く受け持ちます。
- 32 回に 1 回は、選ばなかった方からも読みます。一度遅く見えた SSD を、ずっと使わなくなるのを防ぐためです。
- 2 枚目からの読み出しに失敗したら、その分は 1 枚目から読み直し、以後は 2 枚目を使いません。2 枚目が外れても、
  答えは止まりません。
- どの SSD から読むモデルでも効きます（DeepSeek V4 / V4.1、GLM-5.3-Flash など、エキスパートを SSD から読む
  もの）。答えている最中の読み出しと、起動時に RAM と VRAM へ読み込む処理の両方に効きます。

## 効きやすい PC、効きにくい PC

| 効きやすい | 効きにくい |
| --- | --- |
| メモリが少ない（64 GB など）、SSD から読む量が多い | モデルがほぼメモリに入る（SSD 待ちがもともと小さい） |
| 2 枚とも CPU 直結の M.2、同じくらいの速さ | 2 枚目が遅い（SATA、USB 3.x）|
| 1 枚目が遅め（3〜4 GB/s 級） | |
| 大きい量子化（GPU + メモリより大きいほど） | GPU + メモリに入るモデル（Qwen3.8、DeepSeek V4 0731 UD-Q2_K_XL など） |

減るのは SSD 待ちだけなので、全体の効き目は「1 トークンのうち SSD 待ちが何割か」で決まります。同じ GPU 32 GB + メモリ 96 GB でも、
V4.1 UD-IQ1_M（250 GB）では数 %（見込み）、UD-IQ2_XXS（300 GB）で +4.5%、それより大きい量子化ではもっと効くはずです。数 % でも、
何千トークンも出す長い答えでは積み重なり、出力は変わりません。

- この PC（Ryzen AI Max+ 395 のミニ PC）では、2 枚目が USB4 で、GPU（OCuLink）と iGPU と同じ APU の中の通り道を
  通ります。それでも効きました。ただ、ほかに重い書き込み（ダウンロードなど）があると、2 枚のほうが遅くなった回が
  ありました。測るときは、ほかの読み書きを止めてください。
- `STRATA_GLM_DISK_LANE=1`（SSD から読んだエキスパートを iGPU で計算する）との組み合わせは、1 枚でも 2 枚でも遅く
  なりました（この PC：49 → 50 ms、51 → 64 ms）。組み合わせないでください。

## RAID 0 との違い

| | RAID 0 | STRATA_GLM_MIRROR |
| --- | --- | --- |
| 準備 | 2 枚を 1 つのドライブに組み直す（OS やファイルシステムからやり直し） | 2 枚目にファイルをコピーするだけ |
| 1 枚が壊れたら | 全部読めなくなる | 残った 1 枚で動き続ける |
| 速さの違う 2 枚 | 遅い方に引っ張られる | 速さに応じて読む量を分ける |
| 容量 | 2 枚の合計 | 2 枚目に同じファイルの分が要る |

## ほかのエンジンとの違い

確認した範囲（Strata v0.2.7.1、Project Maya v1.1.36、llama.cpp、ik_llama.cpp、KTransformers、2026-10-29 時点）では、
答えている最中に 2 枚の SSD から同じファイルを読み分ける仕組みは見当たりませんでした。

- Project Maya の `MAYA_DS4_LOAD_INTERLEAVE` は、シャードを 2 枚に**分けて**置き、起動時の RAM への読み込みを速くする
  ものです。答えている最中の SSD 待ちには効きません。
- Strata の `STRATA_MIRROR_MIB` は、エキスパートの写しを RAM に置く設定で、SSD とは関係ありません。

## 制限

- Linux だけです（O_DIRECT で読むときに使います）。Windows では、設定しても 1 枚目だけから読みます。
- 2 枚目のファイルは、1 枚目と同じ版でなければなりません。配布元がファイルを差し替えたときは、2 枚目もコピーし直して
  ください（大きさか先頭・末尾が違えば、ログに警告が出て、2 枚目は使われません）。
- 2 枚目の容量は、コピーしたシャードの分だけ要ります。
- フォルダは `:` 区切りで複数書けます。シャードごとに、最初に見つかったフォルダの写しを使います（シャードを 2 枚目と 3 枚目に分けて置けますが、1 つのシャードを 3 枚以上から読み分けることは未対応）。3 枚目は、同じ速さなら SSD 待ちを 2 枚の半分から 3 分の 1 に
  減らすだけで、伸びは 1 → 2 枚より小さく、チップセット経由の M.2 や、GPU への PCIe（OCuLink / USB4 の x4 では約 7 GB/s、
  この PC の 2 枚の起動時の読み込みで 7.6 GB/s）が先に上限になるので、2 枚までにしています。
